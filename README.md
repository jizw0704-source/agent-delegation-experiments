# AI 跨工具委派实验

**Agent Delegation Experiments — 从“让另一个 AI 干活”到可核验的任务交付。**

这里记录个人使用 AI 工具相互委派任务的实践：怎么交接、怎么跟进、如何检查结果，以及执行过程中有哪些边界没有被遵守。

这不是智能体框架，也不提供已经验证可靠的自动化服务。目前收录两篇探索记录，不构成性能基准或产品排名。

## 第一篇：Codex 委派 WorkBuddy 开发计时器

2026 年 9 月 10 日，在 macOS 上通过 Computer Use（计算机操作），让 Codex 操作 WorkBuddy 的桌面界面，新建任务、发送开发需求，并跟进交付。

**流程：人提出目标 → Codex 通过界面派发 → WorkBuddy 开发与自测 → Codex 核对文件、日志和截图。**

| 观察项 | 本次记录 |
| --- | --- |
| 交付目标 | 本地、离线、单 HTML 文件的中文倒计时／正计时工具 |
| 开发执行者 | WorkBuddy；Codex 没有代写或修改计时器代码 |
| 委派方式 | 桌面界面输入需求并发送，没有使用 WorkBuddy 专用 API |
| 初始需求 | 1 次发送，无追加开发指令 |
| 任务耗时 | WorkBuddy 界面显示 7 分 2 秒，不含全部前后检查时间 |
| 执行者测试记录 | 63 项逻辑测试、25 项浏览器测试通过 |
| 上层检查 | 查看产物代码、测试日志与生成截图；未独立完成浏览器交互验收 |
| 发现的边界问题 | 明确要求不修改用户级技能，但 WorkBuddy 仍更新了既有技能文档 |
| 成本结论 | 无两端 token 明细、无单独使用 Codex 的对照，不能证明节省 token 或费用 |

**本次结论：跨工具委派与产物交付成功复现；独立验收尚不完整，权限约束并未全部遵守。**

## 与 Agent Bridge 的关系

[Agent Bridge](https://github.com/jizw0704-source/agent-bridge) 探索个人 AI 在主人授权范围内交流与协作。本仓库是相关实践记录，不是 Agent Bridge 已实现的功能。

本次是同一人的两个工具之间的委派；它不能直接证明不同主人之间的授权、隐私和协商机制已经可行。

可能的后续方向是：由桥接层明确任务、状态、产物与授权信息，优先使用受支持的接口，必要时辅以界面操作。是否优于纯 Computer Use，需要单独验证；消息中的权限声明不能代替执行端的权限隔离。

## 公开范围与证据边界

本仓库只发布整理后的文档，不附原始聊天、完整桌面截图、账户信息、个人本地路径或计时器源码与原始日志。文中的数量与过程是根据本次本地观察整理，外部读者暂不能仅凭本仓库重跑并核验全部结果。

AI 参与了文档整理。观察事实、执行者自报结果和未来推断在正文中分别标注。请勿将“测试通过”理解为安全、全部功能或所有浏览器均已验证。
