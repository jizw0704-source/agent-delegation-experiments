## 1. 成长任务：交付和领奖是两个步骤

通过 WorkBuddy 的灵感入口，选择学习目标管理台方向，以界面当时标示限时免费的 Hy4 preview 模型执行，任务界面显示“允许完全访问”。这只是当时设置快照，不能证明默认设置在所有任务或重启后都保持。

委派目标是精简、离线、单文件 HTML：新增学习目标，填写总量与已完成量，更新进度与百分比，使用浏览器本地存储保存，并标记示例目标。任务要求限定在新任务目录内创建文件，避免修改其他项目、读取私人文件、安装技能、使用收费服务或部署上传。

WorkBuddy 最终生成 `study-goal-tracker.html`。执行过程中经历生成、检查和测试脚本修正；成长页面并非立即计入，后来出现可领取入口，再领取“探索优秀灵感”奖励。

**产物已生成、平台计入任务、奖励已领取，必须分别核对。** 文件存在不证明交互全部正确，执行者自测也不替代独立验收。本次归档未补做完整浏览器交互测试，也没有模型 token 或账单明细，不能给出精确费用或节省比例。

用户随后指出仍有大量任务未完成。应如实保留这个缺口：完成两项不等于完成整个成长计划。接下来需要建立逐项状态表，区分可直接完成、需要额外条件、已完成待领奖和跨日累计；不能仅因某任务暂时无法完成而停止所有可推进的任务。

## 2. 专家是什么形式保存的

先查阅官方专家格式，再检查已使用的“工作台搭建师·小台”。本地存在角色文件、插件配置、头像与下载标记；配置版本为 1.5.1。角色正文包含工作流程，也包含 WorkBuddy 资料库相关要求。

由此确认：专家是一个文件包，核心指令可用 Markdown 表达；目录清单、已下载文件与平台运行能力是不同层次。

## 3. 程枢：从猜测到前后对照验证

目标是“程枢 · AI Agent 开发工程师”。初次搜索缓存时出现其他相近职业名称，无法据此认定同一专家。随后根据用户截图及实时界面确认准确名称。缓存清单没有完整反映实时市场，因此“缓存搜不到”不能推出“专家不存在”。

实验步骤：

1. 记录专家下载目录，当时只有 `workspace-builder` 专家包。
2. 在实时界面点击“召唤程枢”。
3. 确认界面进入已选中 AI Agent 开发工程师的新任务输入页。
4. 再检查目录，新增 `ai-agent-engineer` 包。
5. 读取配置和角色文件，核对名称“程枢”、职业与版本 1.0.0。

**这次实测中，召唤即可触发专家文件下载，无需发送第一条消息。** 界面预填了示例需求，但未点击发送。该结论适用于本次版本和专家，不能据单一样本保证所有专家都使用相同机制。

下载包结构如下（仅记录结构，不转载第三方指令全文）：

```text

├── .codebuddy-plugin/plugin.json
├── agents/ai-agent-engineer.md
├── skills/agent-craft/
│   ├── SKILL.md
│   ├── references/
│   │   ├── agent-patterns.md
│   │   ├── tool-design.md
│   │   ├── error-matrix.md
```

角色 Markdown 由开头的 YAML 元数据和正文组成。元数据包含名称、职业、轮次上限及关联技能；正文包括角色定位、能力边界、工作步骤和输出约束。配置文件负责关联角色、技能与展示信息。文件中的能力描述是设计意图，不能当作真实工程能力的测试结果。

## 4. 在 Codex 中复用：目前到哪一步

当天研究区分了三条路线：将专家流程适配为 Codex 技能；适配其工具与服务依赖；继续由 Codex 通过界面委派 WorkBuddy 执行。当前只验证了文件可读与界面委派，并未完成专家迁移或同任务对照测试。

迁移前应核对复用许可、平台专属能力与工具映射。复制 Markdown 本身不会自动获得 WorkBuddy 的资料库、连接器、模型或运行权限。下载文件中的指令也不能自动成为当前执行授权。

当天还查阅了 WorkBuddy 开放接口，看到本地助理消息及云端任务等能力，但未实测接口，也未确认创建任务时能指定市场专家。不能将文档可行性写成已经打通。

## 5. 下一步与复盘

- 成长计划：逐项核对剩余任务、完成条件及领奖状态，先推进无需额外条件的项目。
- 产物验收：独立验证学习目标管理台的新增、修改、刷新持久化及异常输入。
- 专家复用：先检查许可和依赖，再做一个明确范围的 Codex 适配试验。
- 对照实验：同一需求分别执行，记录结果、人工干预次数、耗时和可获取的成本明细。

本任务更早还涉及 WorkBuddy 升级、模型与权限设置，以及聊天应用代回复尝试。它们属于此前记录，未作为今天新增成功案例；本篇不公开联系人、消息正文或账户资料。
